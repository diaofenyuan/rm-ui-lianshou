## 理解实际链路

训练中的完整路径是：机器人裁判系统 → 官方赛事引擎 → 官方选手端 → 自定义客户端。图传必须先在官方选手端正常显示，才会向自定义客户端转发；官方选手端与自定义客户端需要使用同一机器人 ID。见自定义客户端配置手册第 9 页。

**`192.168.1.2` 和 `192.168.12.1` 属于不同链路，不应混淆。** 协议中的 MQTT 服务地址 `192.168.12.1`，在官方学生版搭建方式中配置在官方选手端连接自定义客户端的那张网卡上。

| 设备 / 网卡 | 地址 | 连接 |
|---|---|---|
| 裁判系统路由器 LAN | `192.168.1.1/24` | DHCP 开启，2.4 GHz 支持 |
| 官方裁判端 / 服务器电脑 | `192.168.1.2/24` | 有线接路由器 LAN；另保证互联网可用 |
| 官方选手端第一张有线网卡 | DHCP 自动获取 | 有线接裁判系统路由器 |
| 官方选手端第二张有线网卡 | `192.168.12.1/24` | 有线直连自定义客户端；不填写默认网关 |
| 本项目所在电脑 | `192.168.12.2/24` | 连接官方选手端第二张网卡 |

上表依据联网手册第 4–5 页及自定义客户端手册第 6–9 页。路由器 WAN / 外网网段应避开这两个子网；SSID、认证、无线参数、模块配置按官方手册及队伍设备统一设置。不要把模拟端的 `127.0.0.1` 用在两台电脑间通信。

## 有设备后的操作顺序

1. 从官方学生版页面取得相互匹配的赛事引擎、选手端和工具；按发布说明检查主控和图传模块固件。注意图传发送端的固件与核心文件分别有版本。
2. 按上表搭建网络，在裁判端启动 `RoboMasterEngine.exe`，完成本地 IP 和外网检测，并使用自己的 DJI 账号登录。其服务器由裁判端自动启动。
3. 在裁判端创建练习比赛、确认对应机器人在线，熟悉准备、自检、倒计时、比赛、暂停与结算操作。具体按钮依官方页面中的最新《裁判端界面说明手册》操作。
4. 运行官方选手端，登录目标机器人，先确认官方画面与比赛信息可用；然后接入本项目电脑。官方选手端需要两张有线网卡。
5. 在本项目选择“连接实机”：MQTT 服务端 `192.168.12.1`、端口 `3333`、本机监听 `192.168.12.2:3334`，机器人 ID 与选手端一致。
6. 先单独运行 `rm_receive`，核对裁判端切换阶段时的字段变化；结束该接收器后运行图传客户端，避免同一 MQTT Client ID 冲突。最后核对暂停、倒计时、红蓝得分和结算信息。

网络排查先执行 `Test-NetConnection 192.168.12.1 -Port 3333`，确认地址、网卡、路由和服务监听。MQTT 正常但无图像时，先确认官方选手端已出图，再检查 UDP 3334、网卡绑定和 FFmpeg。原官方手册包含关闭防火墙的步骤；本项目脚本不修改防火墙，训练时优先配置所需应用和端口的定向放行。

## 本次实现采用的协议约定

- MQTT 直接承载 Protobuf 二进制，Topic 严格为 `GameStatus`，最高 QoS 1，官方发布频率 5 Hz；Client ID 是机器人编号。
- V2.0.0 的 GameStatus 共十个 `optional` 字段。第 9 项 `game_result` 和第 10 项 `end_reason` 为新版新增结算信息，非结算时值为 255。完整类型与编号保存在项目 `.proto`。
- UDP 3334 承载 HEVC，包头依次是帧编号 `uint16`、分片序号 `uint16`、完整帧字节数 `uint32`，均大端；包长最多 1400 字节，净载荷最多 1392 字节，无重传。
- 本地 Broker 仅绑定回环地址，以 5 Hz 发布协议消息；测试视频先编码成 HEVC，再按包头和长度分片发送，客户端必须经过真实网络接收和解码才能出图。

目前可完成无硬件演示和代码学习。真实服务器部署、模块上线、正式图传与机器人 ID 绑定仍需有设备后按上述步骤验收，不将模拟测试结果当作实机验收。
