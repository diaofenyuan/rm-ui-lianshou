# RoboMaster 自定义客户端「单兵模式 + 总控模式」改造计划

对象：`src/`（当前 `dist/rm_client.exe` 与源码同步）
定位复核：本客户端运行在**副电脑**上，正式比赛时操作手直接操控选手端。本端不做控制，只做**战场信息收集与态势查看**。

**v2 修订说明**：v1 曾把「多 Client ID 并发连接池」当作总控模式的地基。**该方案已否决** —— 官方比赛服务器大概率直接禁止同一来源的多个 MQTT 连接。因此 v2 把整个方案重新锚定在**单连接**这一硬约束上：删掉连接池（v1 §2、D10–D12），总控模式从"新建一套多机数据模型"改为**在现有总控台上做字段与形态升级**，队友面板的字段范围按协议实际下发口径收敛，批次顺序随之重排。

## 0 设计边界（先定死三条，后面所有结论都由它推出）

| 边界 | 内容 | 推论 |
|---|---|---|
| **单连接** | 一个客户端只建一条 MQTT 连接，Client ID 对应一个机器人编号 | 只有**那一台**的单机域数据；队友的单机域数据不可得 |
| **全局域 / 单机域二分** | 全局域广播（全队 + 敌方），单机域按 Client ID 过滤 | 总控模式的信息底座是"全局域"，不是"多台单机域" |
| **图传与 MQTT 无关** | 图传走独立 UDP | 单兵模式的图传不受连接数限制，永远是可靠的底层 |

### 0.1 单连接能拿到什么（决定两个模式的信息上限）

| 类别 | 内容 | 覆盖范围 |
|---|---|---|
| **全局域**（广播，一份） | `GameStatus`、`GlobalUnitStatus`、`GlobalLogisticsStatus`、`GlobalSpecialMechanism`、`Event`、`PenaltyInfo`、`RadarInfoToClient` | **全队 + 敌方** |
| 可得的具体字段 | 全队与敌方血量（10 槽位）、己方累计发弹量、全场位置（雷达 12 槽位）、基地/前哨站血量与状态、经济/科技等级/加密等级、堡垒机制计时、事件流、判罚、阶段/倒计时/局数/比分 | 全队 + 敌方 |
| **单机域**（按 Client ID 过滤） | `RobotStaticStatus`、`RobotDynamicStatus`、`RobotModuleStatus`、`RobotPosition`、`RobotRespawnStatus`、`RobotInjuryStat`、`Buff` | **只有登录的那一台** |
| 不可得的具体字段（队友） | 实时热量、剩余弹量、等级、主控模块状态、复活进度、受伤统计、朝向 yaw、Buff | 队友全部不可得 |

**这条边界直接改写了两件事**：

1. **总控模式能做到的"同时看全队" = 血量 + 位置 + 存活 + 发弹量。** 队友的热量、弹量、等级、复活进度在协议层就没有下发路径，界面**不为它们预留位置**（否则会出现一整列"—"，比不显示更糟）。
2. **单兵模式的队友面板字段收敛为**：兵种 / 编号、血量、存活与阵亡、位置时效（雷达是否给出该点位）。这已是你确认的 5 个队友（1/2/3/4/7）。

### 0.2 一个必须先实测确认的开放问题（影响单兵模式的本机字段）

单机域数据只下发给 Client ID 对应的那一台。副电脑的 Client ID 有两种可能，结论完全不同：

| 方案 | 副电脑的 Client ID | 结果 | 风险 |
|---|---|---|---|
| (a) 用操作手的机器人编号 | 与该台一致 | **能拿到本机的热量/弹量/等级/主控/复活** | 可能与官方选手端**互相挤下线**（同 Client ID 会顶掉旧会话） |
| (b) 用独立的观察者编号 | 与操作手不同 | 只有全局域，**本机单兵字段全部为空** | 单兵模式的本机卡退化为空壳 |

这决定**单兵模式的本机状态卡是否有内容**，也决定 README 里"确认官方选手端登录的是同一编号"这句话的正确含义。**建议实机先做一次最小验证**：副电脑按方案 (a) 连接，观察官方选手端是否掉线；若掉线，则只能走方案 (b)，本机单兵字段改为"不在本端展示"。

在此之前，实现上按**字段自适应**处理：拿到单机域就渲染，拿不到就整块隐藏 —— 两种方案下都不需要返工。

## 1 两个模式的定位

| | 单兵模式 | 总控模式 |
|---|---|---|
| 使用者 | 单个操作手（看自己这台） | 指挥 / 观察位（看全场） |
| 主视觉 | 全屏图传 + 半透明 HUD | 战术地图 + 全队状态列表 |
| 信息底座 | 图传 + 本机单机域 + 全局域 | **全局域**（全队血量、全场点位、经济、机制） |
| 核心问题 | "我还能不能打、队友还剩谁、敌人从哪来" | "全队什么状态、敌方在哪、机制烧到谁了" |
| 与现有代码的关系 | **重构**（单兵视角 → 单兵模式） | **升级**（总控台 → 总控模式，骨架复用） |

两个模式共用同一条 MQTT 连接与同一份状态模型 —— 不允许两套数据结构、两套接线逻辑。这也是单连接约束下的自然结果：切换模式**不重连、不换数据源**。

│            │                                │                │

│ 兵种/血量   │        图传画面                 │  雷达点位       │
│ 5 个槽位    │    （1920×1080 HEVC）          │  双方 12 槽位   │
│ 1/2/3/4/7  │                                │                │
├────────────┤                                │                │
│ 本机状态    │                                │                │
│ 热量/弹量/主控│  ← 依赖 §0.2 的 Client ID 结论，拿不到则整块隐藏  │

### 2.2 总控模式（在现有总控台骨架上升级）

```
┌────────────────────────────────────────────────────────────────┐
│ 阶段 / 倒计时 / 局数 / 双方基地血量 / 经济（比分在此保留）          │
├──────────────┬──────────────────────────┬──────────────────────┤
│ 我方全队       │  中央战术地图（M 键开关）   │ 敌方列表              │
│ 兵种 · 血量/存活│  雷达双方 12 点位 + 本机朝向│ 血量（协议同口径）     │
│ 发弹量 · 位置时效│                         │                      │
│ 阵亡与阵亡计数  ├──────────────────────────┤                      │
│              │  复活状态 · 全队汇总         │                      │
├──────────────┼──────────────────────────┼──────────────────────┤
│ 战场事件       │  数据分析                 │ 图传预览              │
└──────────────┴──────────────────────────┴──────────────────────┘
```

**总控模式的升级点（相对现有总控台）**：

1. 我方列表从"5 行血量"扩展为"兵种 · 血量/存活 · **发弹量** · **位置时效**"，并明确标注阵亡；
2. 新增**全队汇总**：存活 n/5、阵亡列表、缺数据槽位提示；
3. **不新增**热量/等级/复活列（协议不提供，见 §0.1）；
4. 命名统一为「总控模式」。

## 3 快捷键与交互约定

| 键 / 控件 | 作用 | 生效范围 |
|---|---|---|
| `Ctrl+Tab` | 单兵模式 ⇄ 总控模式 | 全局 |
| `F10` | 进入 / 退出**专注模式**（单兵模式：全屏图传 + HUD 全部保留） | 单兵模式 |
| `Esc` | **退出专注模式**（专注态含全屏，一次退到底）；非专注的纯全屏态则退全屏 | 全局 |
| `F11` | **纯全屏，无 HUD**；与专注态互斥 | 全局 |
| `M` | **开关地图**：单兵模式切右上角 HUD 地图，总控模式切中央战术地图 | 两个模式 |
| 复选框「信息叠加」 | 开关 HUD 整体（关掉只剩纯图传） | 单兵模式 |

**Esc 链必须重写**：现在是"先判全屏、再判专注"（`window.cpp:496-498`），新语义下专注态本身包含全屏，顺序必须先判专注，否则会出现"退了全屏但仍在专注态"的中间错误状态。

**M 键的实现细节**：底部日志是 `QPlainTextEdit`（`window.cpp:81`），焦点在其中时按 M 会被当作文本输入。`QShortcut` 默认 `WindowShortcut` 上下文仍会抢键，必须显式判断焦点控件、或在日志框聚焦时临时禁用该 shortcut，否则操作手一打字就切地图。

## 5 逐条改动

### 批次 A —— 单兵模式形态（P0）

**D1 命名统一**
`单兵视角` → `单兵模式`（`window.cpp:260-261`、`:589`），`总控台` → `总控模式`（`console_page.cpp:17` 的 objectName、切换文案）。窗口标题（`window.cpp:244`、`:257`）与无障碍名（`setAccessibleName`）一起改。
验收：仓库内 grep "单兵视角"只出现在历史文档中。

**D2 单兵模式页面骨架**
现状：单兵页垂直堆叠（`window.cpp:269-297`）——比赛概览固定 100px + 画布 + 工具行 + 提示条 + 诊断，图传被上下挤；`VideoCanvas`（`window.h:20-31`）同时装画面、比分叠加和 `allyBlue`/`operatorName` 等业务状态。
改法：
1. `VideoStage` 只画画面，`hasHeightForWidth()` 固定 16:9，消除 `KeepAspectRatio` 的黑边（`window.cpp:157`）；暴露 `imageRect()`。
2. `OperatorHud` 作为 `VideoStage` 的子控件、几何对齐 `imageRect()`（`resizeEvent` 手动定位，**不用布局叠放**），四锚：顶部条全宽；队友面板贴左；本机卡贴左下；地图贴右上。HUD 用非不透明背景自绘半透明卡，父控件的画面自然透出。
3. 业务状态（`allyBlue`、`currentRobotId`、`operatorName`）上移到 `OperatorPage`，`VideoStage` 保持无状态。
验收：1024×720 与 1920×1080 两档下，图传可视高度 ≥ 窗口高度 85%（非专注态、日志折叠）；HUD 不出 `imageRect()` 边界。

**D3 顶部信息条替换 `MatchSummary`，移除比分**
现状：`MatchSummary`（`window.h:33-40`、`window.cpp:96-138`）固定 100px，内容是红方得分/蓝方得分/阶段/倒计时/局数/已过/结算结果。
改法：删除 `MatchSummary`，新建 `StatusStrip`（高 52–60px）三段：
- **左**：本机身份（阵营 · 兵种 · ID）+ 存活/阵亡；
- **中**：阶段名 + 阶段倒计时（保留最后 10 秒紧急态 `:123-127`），暂停/结算时整条换色并写明原因；
- **右**：第 N / M 局 + 特殊机制计时（`status::mechanismText`，己方堡垒被占 / 对方堡垒被占）+ 两枚链路时效点（比赛信息 / 图传）。
目标：用"还剩多少秒 + 我还能不能打 + 机制在烧谁"替换"几比几"。**总控模式的比分条保留不变。**
验收：单兵模式下不出现任何比分数字；暂停 / 结算 / ≤10 秒三种状态有明显区分。

**D6 专注模式 = 全屏，Esc / F11 语义**
现状：`setFocusMode()`（`window.cpp:528-535`）只隐藏侧栏、日志、诊断，**不切全屏**，`MatchSummary` 仍在。
改法：`setFocusMode(true)` 时 `showFullScreen()` + 隐藏右侧配置栏、底部日志、诊断条；HUD 全部保留；HUD 略降不透明度，鼠标进入 HUD 区域恢复。`Esc` 按 §3 新顺序重写；`F11` 改为纯全屏无 HUD，与专注态互斥。
验收：F10 后 `isFullScreen() == true` 且 HUD 可见；Esc 一次回到窗口态，不出现"退了全屏但仍在专注"的中间态。

**D7 画内叠加语义重定义**
现状：`overlay`（`window.cpp:280`、`:189-240`）叠的是比分+局数，手绘白色面板。
改法：删除原手绘比分面板；复选框改名「信息叠加」，控制 HUD 整体显隐（关闭即纯图传）。这样 HUD 只有一份实现，不再有两套锚定逻辑。
验收：关闭叠加后画面内除断流提示外无任何绘制。

**D9 自检、证据与文档同步（必须与 A 批同批提交）**
现状：`runUiChecks()`（`window.cpp:708-794`）硬编码 `matchSummary->isVisible()`、`canvas->width() > normalWidth`、`canvas->overlay` 等断言；`tools/check_link.py:50-64` 断言 `ui_checks_passed`；`build.ps1` 依赖两个 check 脚本。
改法：断言改为"顶部条可见且不含比分""队友面板 5 行""地图可见且 `markerCount() > 0`""按 M 后地图隐藏、再按恢复""F10 后全屏且侧栏隐藏""Esc 后回到窗口态""关闭叠加后 HUD 隐藏"；`metrics()` 增加 `operator_hud_visible`、`operator_teammate_rows`、`operator_map_markers`、`operator_map_visible`、`operator_focus_fullscreen`；证据截图改名并在文档记录新旧映射。
**这一批绝不能拖到后面**：骨架一动，`--ui-checks` 当场失败，`build.ps1` 连带红，回归防线等于零。

### 批次 B —— 单兵模式信息件（P1）

**D4 队友状态面板 + 本机卡**
改法：`TeammatePanel` 按协议固定槽位 **1/2/3/4/7 出 5 行**（`match_state.h:59-63` 的 `allyHealth(0..4)`），每行：兵种名 + 血量数字 + 血条 + 存活/阵亡 + 位置时效点（该槽位在雷达 12 点位里是否有对应点位）。本机所在行高亮。
左下本机卡：血量/热量（含上限）、弹量、等级、主控状态 —— **整块按字段自适应**，单机域未收到时隐藏（对应 §0.2 的两种 Client ID 方案）。
**明确不做**：队友热量、队友弹量、队友等级、队友复活进度（协议不提供）。
验收：5 行全部来自协议槽位；槽位缺失显示"未提供"而非消失；`UnitStatus` 过期整面板灰显。

**D5 右上角全场地图 + M 键开关**
改法：`MinimapPanel` 增加 HUD 模式（半透明深色卡底、去页脚、紧凑点位、`is_high_light` 环保留 `minimap.cpp:139-143`）；底图与坐标**完全复用** `:/map/field.jpg` + `map_transform`（含蓝方 180° 视角），不重新实现坐标。M 键开关显隐，状态记住（`QSettings`）。总控模式的中央地图复用同一控件，M 键也切它。
验收：地图常驻可见；M 键切换即时生效且不与日志输入冲突；数据过期标注"仅显示最后已知位置"。

**D8 渲染分层与性能**
现状：每来一帧就 `canvas->update()`（`window.cpp:452-454`），`paintEvent` 同时画画面与叠加，1080p60 下叠加面板跟着 60fps 重绘。
改法：`VideoStage` 只重绘画面；`OperatorHud` 独立刷新节奏（200ms ticker + 数据域信号，约 5–10Hz），**不跟帧率**；HUD 半透明底卡用预渲染 `QPixmap` 缓存；地图复用 `MinimapPanel` 的 `rendered/renderedKey` 缓存（`minimap.cpp:96-107`）。
验收：`build/integration-metrics.json` 中 `decoded_frames` 与改造前同量级；实机 1080p60 单独压测并记录（README 已注明该项本身未验证）。

### 批次 D —— 总控模式升级（P2）

> v1 的批次 C（连接池）已整体取消。总控模式不需要新的数据层 —— 现有 `MatchState` 与 `ConsolePage` 已经覆盖全部可得数据，本批只做字段与形态升级。

|---|---|---|---|

| 编号 | 风险 | 影响 | 缓解 |

## 9 需要你确认的取舍

**C1（新增，最关键）** §0.2 的 Client ID 方案：副电脑连接时用**操作手的机器人编号**（能拿到本机单兵字段，但可能与官方选手端挤下线），还是用**独立观察者编号**（安全但本机单兵字段为空）？建议先做一次实机最小验证。**在这个结论出来之前，单兵模式的本机状态卡按"有则显示、无则隐藏"实现。**

**C2 队友面板字段** 已确认只显示能获得的 5 个队友（1/2/3/4/7）。基于 §0.1，这 5 行显示：兵种 · 血量 · 存活/阵亡 · 位置时效。是否同意？要不要也带上"己方累计发弹量"（口径待核）？

**C3 总控模式是否还需要"同时看全队"以外的能力** 现在的口径是：全队血量 + 全场点位 + 经济 + 机制 + 事件。有没有指挥位真正需要、但上表没覆盖的信息？

**C4 M 键作用域** 按"两个模式都切各自的地图"设计（单兵切右上角 HUD 地图，总控切中央战术地图）；日志框聚焦时屏蔽。是否同意？

**C5 顶部信息条内容** 默认组合：阶段名 + 阶段倒计时 + 局数 + 机制计时 + 本机身份 + 两枚链路时效。请确认：(a) 要不要加"双方基地血量 / 存活比"这类局势摘要（不含比分）；(b) 要不要加最近一条战场事件的短时提示。

**C6 F11 是否保留** 专注态（F10）已含全屏，F11 只作"纯全屏无 HUD"。不需要纯画面模式的话可以删掉，键位更干净。

**C7 比分** 单兵模式清零、总控模式保留 —— 是否同意？

**C8 非专注态下侧栏与日志的去留** 单兵模式默认仍显示右侧配置栏与底部日志折叠条（现场需快速重连），我建议保留但收窄。
