# 多机器人连接池说明

本文记录总控模式连接池的 topic 分配、状态归集、去重和现场验收口径。连接池只读 MQTT 数据，不发送机器人控制命令。

## 连接布局

启动时按所选阵营建立 1–7 号共 7 条连接；选中的操作位排在第一位，作为主链路。蓝方机器人 ID 为兵种编号加 100，红方直接使用兵种编号。

| 链路 | Client ID | 订阅 | 写入位置 | 用途 |
|---|---:|---|---|---|
| 主链路 | 当前操作位 | 协议表 2-1 的 14 个 topic | `MatchState` 全局域 + 主机快照 | 比赛信息、事件、雷达、图传关联的主状态 |
| 队友链路 | 其他 1–7 号 | 7 个单机域 topic | `MatchState::RobotSnapshot[robot_id]` | 热量、弹量、等级、主控、复活、位置等单机数据 |

7 条链路的本地模拟订阅总数为 `14 + 6 × 7 = 56` 个 topic。全局域只由主链路进入比赛状态模型，避免事件时间线和比分被重复写入。

## 状态与去重

- `RobotLinkPool::LinkStatus` 记录连接是否就绪、订阅数、累计接收数、最近一条消息年龄和重连次数；`LinkPoolPanel` 按 Client ID 展示这些字段。
- 建连采用 200–400 ms 的串行错峰；单条链路断开后由 `StatusReceiver` 在约 2 秒并带 0–500 ms 抖动后重连，不阻塞其他链路。
- 连接池为单机域信号附加所属机器人 ID，写入对应快照；缺少该域时保留“未收到”，超过时效阈值则标记“数据过期”，不借用其他机器人的值。
- 事件只接受主链路，且以 `(event_id, param)` 在 1.5 秒窗口内去重；主链路重投不会刷屏，队友链路不会重复追加全局事件。
- `RobotLinkPool::stop()` 先使代次失效、断开旧接收器，再清空链路表；排队的旧信号不会访问已删除的接收器。
