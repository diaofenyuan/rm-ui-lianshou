## 1 问题一：阵营显示错乱（P0，已修）

**现象**：选蓝方工程（ID 102）连接后，总控台"我方机器人"里显示的是对手（红方）的数据。

### 1.1 我方/敌方血量槽位取反 —— 确凿的代码 bug

- 协议定义明确：`proto/rm_messages.proto:11` 与 `src/match_state.h:59` 都写明 `robot_health` 索引 **0–4 为己方** 1/2/3/4/7 号、**5–9 为对方**。
- 实现相反：`src/match_state.cpp:205-213`

```cpp
std::optional<quint32> MatchState::allyHealth(int index) const {
    const int offset = index + kSideHealthCount;   // ← 取到了"对方"槽位
    if (index < 0 || offset >= unitStatus.robot_health_size()) return std::nullopt;
    return unitStatus.robot_health(offset);
}
std::optional<quint32> MatchState::enemyHealth(int index) const {
    if (index < 0 || index >= unitStatus.robot_health_size()) return std::nullopt;
    return unitStatus.robot_health(index);          // ← 取到了"己方"槽位
}
```

- 影响面：`src/ui/robot_list.cpp:34`（面板标题"存活 x/5"）与 `:88`（每行血量）全部左右颠倒，且两个函数缺 `index >= kSideHealthCount` 上界检查（传 6–9 会读到错误槽位而不报错）。
- 对照：雷达槽位 `enemyRadar/allyRadar`（`match_state.cpp:214-222`）与 `proto:165` 一致，是**对的**；`base_health`/`enemy_base_health`、`total_damage_ally/enemy` 都是协议自带的己方/对方口径，直接用即可。**所以只有"机器人血量"这一组反了**——症状就是"只有机器人血量对不上"。
- 改法：两个函数对调取址 + 补上界检查，约 6 行。

### 1.2 本地模拟的单兵身份没跟随所选阵营/兵种

- `tools/launch_demo.py:28` 启动模拟端时**没有**传 `--robot-id` → 用默认值 `104`（蓝方 4 号步兵，`tools/simulator.py:282`）；`:36` 启动客户端时也没传 → 用默认值 `3`（红方 3 号步兵，`src/main.cpp:11`）。**默认演示本身就是错位的。**
- 模拟端的 `RobotStaticStatus / RobotDynamicStatus / RobotPosition / Buff / RadarInfoToClient / Event` 只发布**一台**机器人的数据（`simulator.py:221-235`），它不代表你在界面里选的那台。
- 影响：无论界面里选什么，"本机"行明细（热量/弹量/等级/主控）、小地图上的本机位置与朝向、雷达高亮都来自 ID 104 那台 → 出现"界面显示蓝方身份、数据却是另一台机器人"的错位。
- 改法：
  1. （10 行级）`launch_demo.py` 增加 `--robot-id`（默认 104），并**同时**透传给模拟端与客户端：`simulator.py --robot-id <id>`、`rm_client.exe --connect --robot-id <id>`，两侧天然同阵营。
  2. `README.md` / `docs/console-design.md` 补一句："本地模拟的单兵数据固定为 `--robot-id` 指定的那一台，切换阵营/兵种后需以相同 ID 重启模拟端"。
  3. （Backlog，P2）模拟端改为按订阅方视角发布：对多个 `robot_id` 各发布一套单兵数据，客户端选谁都能对。成本高但最接近实机。

### 1.3 文案口径不统一："我方/敌方"与"红方/蓝方"混用

## 2 问题二：兵种切换（P1）

### 现状
- 切换只在重连后生效：`window.cpp:473-475` 判断 `pending` 并把按钮文案改成"应用兵种并重连"，`consolePage->setRobot()` 只在 `startConnection()`（`:578`）里调用。设计如此，但提示太弱：身份行只有一句"点击下方按钮应用切换"，待应用的差异没有突出。
- `robotId` 只读（`:280`），只能靠"阵营 + 兵种"组合出 ID；实机要求与官方选手端登录编号一致，缺少手工指定入口。
- 连接中改兵种后，总控台的阵营/列表要等重连才变，容易被当成"没生效"。

### 改法
1. 待应用提示加强：顶部身份行加"（待应用）"角标，`connectButton` 高亮为主色并写明"应用兵种并重连"；`profileHint` 改为"当前连接：红方 3 号步兵（ID 3）｜已选：蓝方 2 号工程（ID 102）"。

3. 身份切换写一条事件日志："身份切换：红方 3 号步兵 → 蓝方 2 号工程（待应用）"。
4. `ConsolePage::setRobot()` 的调用点从"仅连接时"扩展到"连接时 + 断开时（回落到所选身份）"，避免总控台停留在上一次的阵营。

## 3 问题三：本地/实机切换、连接参数与端口"滑不动、改不了"（P1）

### 现状（逐条对应代码）
1. 配置栏是 `QScrollArea`（`window.cpp:265-268`）：**固定宽 312**、关掉横向滚动条、内容 `setWidgetResizable(true)`；滚动条样式只有 7px 宽且无轨道（`theme.h:73-76`），几乎看不见。
2. 内容高度：选择操作位 + 链路状态 + "GameStatus 全局信息"10 字段 + 展开后的连接参数（服务端、IP、两个端口、本机监听 IP、FFmpeg 路径、选择程序按钮）远超视口 → 端口与 FFmpeg 必须滚动才能触及。
3. **关键交互缺陷**：鼠标停在 `QComboBox` / `QSpinBox` 上时滚轮事件被控件自己消费 —— "想滚下去看端口"会被解释成"改参数"：`数据来源` 一滚就从"本地模拟"变"连接实机"，并连带把 `host`/`bindIp` 改成 `192.168.12.x`（`:376-381`），没有任何提示。这就是"滑动 = 改不了 / 改乱了"的来源。
4. 窗口尺寸不匹配：`setMinimumSize(1000,720)` + `resize(1360,840)`（`:221`），但总控台三列各有 `setMinimumWidth(225/260)`（`console_page.cpp:36,38,43`），实际最小宽度约 1180px；在 1366×768 / 1280×720 上窗口容易被屏幕裁掉 —— 截图里右侧栏与底部被切就是这个原因。此时侧栏底部的端口/FFmpeg **和滚动条本身**都在屏幕外，就真的"滑不到"。

### 改法
1. **滚轮策略**（最直接解决"滑不动"）：给配置栏装事件过滤器，对 `QComboBox` / `QSpinBox` 的 `wheel` 事件 `ignore()` 并转交 `sidebar->verticalScrollBar()`——"滚轮永远滚面板"；控件改为**聚焦后**才用 ↑↓ / 滚轮改值（`setFocusPolicy(Qt::StrongFocus)`）。若你们更习惯"悬停即改"，则改成需要 `Ctrl+滚轮`，二选一即可。
2. **参数误改防护**：`active` 状态下切 `mode` 时保留原 `host`/`bindIp` 直到点连接，并显示"参数将在重新连接后生效"；端口框失焦校验（1–65535、MQTT ≠ 图传端口）。
3. **参数可见、可留存**：
   - 默认展开连接参数，或用 `QSettings` 记住展开态；
   - `QSettings` 记住上次的 阵营/兵种/来源/主机/端口/监听 IP/FFmpeg 路径，重启不用重填；
   - 侧栏顶部加一条吸顶小结："本地模拟 · 127.0.0.1 · 3333 / 3334"。
4. **滚动条与布局**：
   - `QScrollBar:vertical` 宽度提到 10px、加轨道底色与 hover 态，让"能滚"看得见；
   - `sidebar->setFixedWidth(312)` → `setMinimumWidth(280)` + `setMaximumWidth(360)` + `QSizePolicy::Preferred`；总控台三列的 `setMinimumWidth` 改为靠 stretch 控制、窄窗口下中央地图优先、两侧列表收窄到 180；
   - 窗口默认尺寸按屏幕可用区自适应：`resize(min(1360, availW*0.92), min(840, availH*0.92))`，`setMinimumSize(960, 640)`；
   - 可用宽度 < 1280 时自动进入紧凑模式（`diagnostics` 折叠、总控台底行改单列）。
5. 可选：把"连接参数"从侧栏拆成独立抽屉/对话框（"高级设置"），彻底不和主配置抢垂直空间。

### 验收
- 1280×720 / 1366×768 / 1920×1080 三档：侧栏能滚到底看到 FFmpeg 路径行与滚动条；鼠标在任意下拉框/数字框上滚动时**面板滚动而参数不变**；切 `数据来源` 不会连带改 host，且提示"重连后生效"。
- 关闭程序再打开，上次的阵营/端口/路径自动回填。

## 4 问题四：实机连接后下方信息栏遮挡图传（P1）

### 现状（逐条对应代码）
1. **画布内两条黑底铭牌压在画面像素上**：`window.cpp:155-167` 把"本地模拟 / 非真实比赛画面"（实机为"实机图传 / RM2026"）画在 `QRect(14, height()-39, …, 26)`，操作位铭牌画在右下 `height()-39` —— 都是**画布内**的固定位置。
2. **等比居中导致铭牌必然压画面**：`:136-137` 用 `Qt::KeepAspectRatio` 居中绘制。实机 1920×1080（16:9）而画布宽高比明显大于 16:9（截图 2 实测约 2:1）时，图像按高度铺满、左右留黑边，**底部 26px 的铭牌正好落在图像像素内**；本地 1280×720 同理。
3. **底部信息栏挤压图传高度**：单兵视角垂直堆叠为 `比赛概览(固定 100px)` + `画布(stretch 1)` + `工具行` + `比赛信息提示条` + `诊断 4 指标`；而日志面板（`:338-354`）是主布局的兄弟节点，`logTabs` 固定 120 + 文本框固定 78 → 展开后约 200+px，在 `QSizePolicy::Preferred/Maximum` 之下图传被压得很矮（截图 2 就是这个状态）。窗口比屏幕高时更严重。
4. 画内叠加面板（`:179-215`）按**画布**宽度算位置（`w = min(width()-32, 540)`），不是按图像实际绘制矩形 → 宽扁画布下与画面错位。

### 改法
1. **铭牌移出画面**：把"实机图传 / 本地模拟"与操作位铭牌从 `paintEvent` 移到画布下方工具行（`videoTools`）作为普通 `QLabel`。若确实要保留为画内 HUD，则改为默认隐藏、鼠标进入画布或最近 3 秒有帧时淡入（`QPropertyAnimation` 控 opacity），实机模式 3 秒后自动隐藏。
2. **画布固定 16:9**：给 `VideoCanvas` 实现 `hasHeightForWidth()/heightForWidth()`（高度 = 宽度 × 9/16），或外包一层 `AspectRatioWidget`。这样图像铺满画布、没有黑边，HUD 只需处理画面四角，不会"压到内容"。若坚持 `KeepAspectRatio`，则把 `imageRect` 提为局部变量，所有铭牌/叠加锚定 `imageRect`，并保证只画在 `imageRect` 内、带半透明底、可关闭。
3. **底部信息栏让位**：
   - `logPanel` 展开时限高：`setMaximumHeight(qBound(160, int(height()*0.28), 260))`，`layout->setStretchFactor(logPanel, 0)`（`pages` 保持 stretch 1），`logTabs/log` 的固定高度改为随可用高度自适应；
   - `diagnostics` 4 个指标并入 `logPanel` 头部一行或移入侧栏，常驻高度从 ~70px 降到 0；
   - 实机 + 专注模式下 `matchNotice` 仅在异常时显示（正常的"比赛信息实时更新"不再常驻占一行）；
   - 增加"沉浸布局"开关：只留画布 + 比赛概览。

### 验收
- 1280×720 / 1366×768 / 1920×1080 三档截图，确认"图传可见区域内只有画面本身（允许四角可关闭的可控 HUD）"，且日志展开时图传高度不低于窗口高度的 45%。
