# 总控台信息架构与坐标口径

本文记录总控台页（`src/ui/console_page.*`）的面板构成、每个面板的数据来源与降级策略，以及地图坐标系的口径。协议事实一律以 `docs/references/RM2026-protocol-v2.0.0.pdf` 为准；未在协议中写明的部分单独列出，不混入结论。

## 范围

- 总控台只做**信息展示与提醒**，不向机器人或服务器发送任何命令（下行命令不在当前范围）。
- 数据来源仅限 MQTT 服务器→自定义客户端消息与本地图传解码结果。

## 面板 → 数据源 → 频率 → 降级

| 面板 | 控件 | 数据来源（topic） | 官方频率 | 缺失 / 过期时的表现 |
|---|---|---|---|---|
| 顶栏比分条 | `ScoreBar` | `GameStatus` | 5 Hz | 超过 1.5 秒标记过期；不推算倒计时，缺失字段显示"未提供" |
| 我方机器人列表 | `RobotListPanel` | `GlobalUnitStatus`（血量槽位）、`RobotStaticStatus` / `RobotDynamicStatus` / `RobotModuleStatus`（本机） | 1 Hz / 10 Hz / 1 Hz | 超过 3 秒灰显；协议未提供除本机外的血量上限，不画比例条 |
| 敌方机器人列表 | `RobotListPanel` | `GlobalUnitStatus`（对方槽位） | 1 Hz | 同上；数据过期只灰显，不隐藏行 |
| 战术地图 | `MinimapPanel` | 官方场地底图（本地资源）、`RobotPosition`（本机位置与朝向）、`RadarInfoToClient`（双方槽位） | 1 Hz / 触发式 | 位置超过 3 秒：底图降对比度并标注"仅显示最后已知位置"；从未收到：显示"等待位置数据"，不画点 |
| 复活状态 | `RespawnPanel` | `RobotRespawnStatus` | 1 Hz | 超过 3 秒显示"数据过期"；未复活时显示正常态 |
| 战场事件 | `EventTimelinePanel` | `Event`、`PenaltyInfo`、`GlobalSpecialMechanism` + 本地推导 | 触发式 | 只追加已确认事件；重复消息不重复入队 |
| 数据分析 | `AnalysisPanel` | `GlobalLogisticsStatus`、`GlobalUnitStatus`、`RobotInjuryStat` | 1 Hz | 缺失字段显示"未提供"，不做估算 |
| 图传预览 | `VideoPreviewPanel` | 已解码主图传帧（本地） | 解码帧率 | 图传中断时显示最后一帧并标注"图传中断" |

时效阈值沿用 `MatchState`：5 Hz 与 10 Hz 域 1.5 秒，1 Hz 域 3 秒。触发的 `Radar` / `Position` 域不参与自动过期判定，由面板按 3 秒自行判断。

## 坐标口径

### 已核实（来源：官方协议 V2.0.0）

- **世界坐标系**：表 1-21（0x020B）正文——"场地围挡在红方补给站附近的交点为坐标原点，沿场地长边向蓝方为 X 轴正方向，沿场地短边向红方停机坪为 Y 轴正方向。"
- **单位**：表 1-14（0x0203）与表 1-21（0x020B）的 x / y 单位均为**米**；朝向单位为**度，正北为 0 度**。
- **雷达坐标单位**：表 1-36（0x0305）与协议 2.2.19 均为**厘米**。
- **场地尺寸**：28 m × 15 m（RMUC 标准场地）。
- **2.2.19 槽位顺序**：对方 1 / 2 / 3 / 4 / 6 / 7 号，己方 1 / 2 / 3 / 4 / 6 / 7 号，共 12 项；`is_high_light` 0 否 / 1 是 / 2 是但目标定位模块离线。

由此得到实现口径：世界坐标 X ∈ [0, 28]、Y ∈ [0, 15]（米），归一化即 `x / 28`、`y / 15`；雷达换算为米需 `/ 100`。

### 底图朝向（据实拍场地地图核实）

底图使用官方场地地图 `assets/map/map.jpg`（2800 × 1500 像素，100 像素 / 米，即 28 m × 15 m），通过 `resources.qrc` 以 `:/map/field.jpg` 打进客户端。实测该素材朝向为：

- 红方端在图像左侧（橙色标识），蓝方端在右侧（青色标识）；
- 红方停机坪在该端上方，即 **+Y 朝上**，因此世界坐标原点位于图像左下角；
- 场地中心对称：蓝方端是红方端旋转 180° 的结果。

因此 `src/map_transform.cpp` 的像素映射对 Y 轴取反，蓝方视角在绘制底图与点位时整体旋转 180°，使双方都看到"我方基地在左"。点位、朝向箭头与底图共用同一变换，不会出现点位与地形错位。

素材权属：底图由使用者提供（官方场地地图）。对外分发二进制或源码前需确认该素材的再分发授权；本仓库未收录任何第三方客户端素材。

### 未核实（按假设实现，实机首次接入时必须复核）

| 项 | 假设 | 复核方法 |
|---|---|---|
| 2.2.13 `RobotPosition` 的 x / y / z 单位 | 协议只写"世界坐标 X / Y / Z 轴"，未标注单位；本项目按**米**实现，与同名的 0x0203 / 0x020B 世界坐标保持一致 | 实机把机器人放在场地一角，读 x / y 数量级：约 0–28 为米，约 0–2800 为厘米 |
| 雷达坐标原点 | 与 0x020B 世界坐标同源 | 把机器人移动到已知位置，对比雷达槽位坐标 |
| yaw 的"正北"方向 | 协议未把"正北"关联到 X / Y 轴；按 **+Y 轴（指向红方停机坪）** 实现，常量集中在 `src/map_transform.h` | 让机器人朝 +X（向蓝方）行驶，检查 yaw 接近 90 还是 0 |

未核实项在界面上不做断言：地图只对本机绘制朝向箭头，并在图例中注明朝向来源为本机测速模块。

## 本地推导 vs 协议事实

| 类别 | 内容 |
|---|---|
| 协议事实 | 阶段、比分、局数、倒计时、基地 / 前哨血量与状态、机器人血量、经济、位置、雷达、事件、判罚、Buff |
| 本地推导 | "存活 n / 5"、位置与数据时效、事件去重、过期标记、镜像视角 |
| 明确不做 | 倒计时推算、位置插值与预测、除本机外的血量上限估算、任何未收到字段的填充 |

## 降级规则

1. **位置类**：超过 3 秒未更新 → 点位灰显、底图降对比度并标注"仅显示最后已知位置"；从未收到 → 显示"等待位置数据"，不绘制任何点位。
2. **状态类**：超过对应阈值 → 数值灰显 + 面板标题行标注"数据过期"，不清空最后值。
3. **链路断开**：保留最后状态并全部标记过期，不重置为初始值；重连后按收到的域逐个恢复。
4. **切换操作位或断开**：清空全部状态（`MatchState::reset`），避免把上一位操作手的数据带过来。
5. **未知枚举与缺失字段**：保留原始数值或显示"未提供"，不做静默改写。

## 布局

总控台页为单页网格，自上而下：

```
┌──────────────────────────────────────────────┐
│ 顶栏比分条（比分 / 局数 / 阶段 / 倒计时 / 基地血量 / 经济）│
├──────────┬──────────────────────┬────────────┤
│ 我方列表  │ 战术地图（中央）        │ 敌方列表    │
│          ├──────────────────────┤            │
│          │ 复活状态              │            │
├──────────┼──────────────────────┼────────────┤
│ 战场事件  │ 数据分析              │ 图传预览    │
└──────────┴──────────────────────┴────────────┘
```

未实装的面板显示"阶段 N 接入"占位提示，整页形态保持完整，便于截图对比与回归。
