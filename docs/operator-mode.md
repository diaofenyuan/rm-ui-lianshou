# 单兵模式与总控模式：页面构成、快捷键与数据边界

本文记录客户端两个模式在**当前代码**中的实现口径。总体改造计划（含尚未实施批次）见
[单兵模式与总控模式改造计划](operator-mode-plan.md)；总控模式各面板的数据来源与坐标口径见
[总控模式设计说明](console-design.md)。协议事实一律以 `docs/references/RM2026-protocol-v2.0.0.pdf`
为准，未在协议中写明的部分单独标注。

## 1 两个模式的定位

| | 单兵模式 | 总控模式 |
|---|---|---|
| 使用者 | 单个操作手（看自己这一台） | 指挥 / 观察位（看全局） |
| 主视觉 | 全屏图传 + 半透明 HUD | 比分条 + 列表 + 中央战术地图 |
| 页面入口 | `src/ui/operator_page.cpp` | `src/ui/console_page.cpp` |
| 核心问题 | "我还能不能打、队友还剩谁、敌人从哪来" | "全场什么态势、谁需要支援" |

两个模式共用**同一条主连接**与**同一份 `MatchState`**，切换模式不重连、不换数据源。切换按钮与
`Ctrl+Tab` 走的是同一个 `MainWindow::switchView()`。

## 2 单兵模式页面构成

```
┌──────────────────────────────────────────────────────┐
│ 顶部信息条 StatusStrip（占满画面宽度，深色半透明）        │
│  左：本机身份 · 存活/阵亡   中：阶段 + 倒计时   右：局数、  │
│                              特殊机制计时、两枚链路时效点  │
├───────────┬──────────────────────────┬───────────────┤
│ 队友面板   │        VideoStage        │  全场地图      │
│ 5 个槽位   │   （固定 16:9，居中）      │  （HUD 模式）   │
│ 贴左       │                          │  贴右上         │
├───────────┤                          │               │
│ 本机卡     │                          │               │
│ 贴左下     │                          │               │
└───────────┴──────────────────────────┴───────────────┘
```

职责切分（一个控件只做一件事）：

| 控件 | 文件 | 职责 |
|---|---|---|
| `VideoStage` | `src/ui/video_stage.h` | **只画画面**，不含任何业务状态；固定 16:9，暴露 `imageRect()` 作为 HUD 的锚定基准 |
| `OperatorHud` | `src/ui/operator_hud.h` | 不绘制自身，只把四块信息件锚定在画面矩形内（`resizeEvent` 手动定位，不走布局叠放） |
| `StatusStrip` | `src/ui/status_strip.h` | 顶部信息条，**不显示比分** |
| `TeammatePanel` | `src/ui/teammate_panel.h` | 队友 5 槽位（1/2/3/4/7） |
| `OwnStatusCard` | `src/ui/teammate_panel.h` | 左下本机卡 |
| `MinimapPanel` | `src/ui/minimap.h` | 地图，`setHudMode(true)` 时改深色卡底与紧凑页脚 |

`VideoStage` 与 `OperatorHud` 是父子关系（HUD 的父控件就是图传），因此 HUD 的矩形恒等于画面矩形，
不需要额外坐标换算。图传尺寸由 `OperatorPage::applyStageWidth()` 按"页面高度减去其它行"反推宽度、
再固定为精确 16:9，从根上消除 `KeepAspectRatio` 黑边与 HUD 锚定错位。

**HUD 尺寸随画面高度缩放**：`theme::hud::scaleFor(imageHeight)` 以 720p 为 1.0，限幅 0.62–2.0。
1080p 专注模式与 1024×720 紧凑窗口下用同一套比例，字号、卡宽、地图尺寸同步缩放。

## 3 快捷键与交互约定

| 键 / 控件 | 作用 | 生效范围 |
|---|---|---|
| `Ctrl+Tab` | 单兵模式 ⇄ 总控模式 | 全局 |
| `F10` | 进入 / 退出**专注模式**（全屏 + 隐藏配置栏、接收统计、日志；HUD 全部保留、卡底略降不透明度） | 全局 |
| `F11` | **纯全屏，无 HUD**；与专注态互斥（从专注态按 F11 会转为纯全屏） | 全局 |
| `Esc` | **先退专注、再退纯全屏**，一次退到底 | 全局 |
| `M` | **开关地图**：单兵模式切右上角 HUD 地图，总控模式切中央战术地图（隐藏整块面板，不是只藏图） | 两个模式 |
| 复选框「信息叠加」 | 开关 HUD 整体（关闭后只剩纯图传） | 单兵模式 |

两处必须小心的实现细节：

1. **Esc 的判断顺序**：专注态本身包含全屏，必须**先判专注**再判纯全屏，否则会出现"退了全屏但仍在
   专注态"的中间错误状态。见 `MainWindow::leaveFullscreenOrFocus()`。
2. **M 键与文本输入**：底部日志是 `QPlainTextEdit`，`QShortcut` 默认的 `WindowShortcut` 上下文会
   抢键，所以 `MainWindow::toggleMap()` 里显式判断焦点控件，焦点在 `QPlainTextEdit` / `QLineEdit` /
   `QSpinBox` / `QComboBox` 内时直接返回，避免操作手一打字就切地图。
3. 两个模式的地图开关分别保存到 `QSettings`（`ui/operator_map_visible` / `ui/console_map_visible`），
   下次启动沿用各自的显示偏好；首次运行默认显示。

## 4 数据边界与降级

| 字段 | 单兵模式 | 总控模式 | 敌方 | 来源 |
|---|---|---|---|---|
| 兵种 / 编号 | 可得 | 可得 | 可得 | 本地选择 + 协议附录二编号表 |
| 血量 | 本机可得 | 全队可得 | 可得 | `GlobalUnitStatus.robot_health`（己方在前 5 项） |
| 热量 / 弹量 / 等级 / 主控 | 仅本机 | 仅本机 | 不可得 | **单机域**，只对绑定那条连接下发 |
| 复活进度 | 仅本机 | 仅本机 | 不可得 | `RobotRespawnStatus`（单机域） |
| 朝向 | 仅本机 | 仅本机 | 不可得 | `RobotPosition`（单机域） |
| 位置（双方 12 槽位） | 可得 | 可得 | 可得 | `RadarInfoToClient`（全局域） |
| 基地 / 前哨站、经济、科技、机制、事件、判罚 | 可得 | 可得 | 同全局域 | 全局域各消息 |
| 图传 | 主图传 1 路 | 主图传 1 路（预览） | — | 独立 UDP 3334 |

**关键约束**：`RobotDynamicStatus` 的结构里没有任何机器人编号字段，因此它只能被单播给"绑定了那台
机器人"的那条连接。想同时看到全队的热量 / 弹量 / 等级 / 主控，就必须为每个编号各建一条连接
（见改造计划批次 C 的连接池）。在当前实现下：

- 队友面板的**血量**与**位置时效点**不需要额外连接（全局域即可），所以现在就能用；
- 队友面板的**热量 / 弹量 / 等级**列**不预留空位** —— 按本项目的既定口径，拿不到的字段不留占位
  （避免大面积 `—`），等连接池到位后按 `TeammatePanel` 的字段自适应规则自动补齐，不返工；
- 队友血条只在本机行绘制比例（本机才有 `RobotStaticStatus.max_health`），队友行以虚线槽标注
  "比例未知"，不按未知上限伪造比例。

全局域过期（`GlobalUnitStatus` 超过 3 秒未更新）时队友面板整块灰显；槽位缺失显示"未提供"，而不是
沿用上一帧数值。

## 5 自检与证据

`dist/rm_client.exe --ui-checks --ui-evidence <前缀>` 会逐项断言并在失败时把具体子项打到标准错误：

- M 键确实绑定了 `QShortcut`（而不是只存在一个没人调用的函数）；
- 兵种选择与"待应用身份"保持、`GameStatus` 十字段面板；
- 总控模式：各面板可见、雷达有点位、时间线有条目、中央地图可开关；
- 单兵模式：信息叠加开关真的控制整个 HUD、顶部条可见且**不含比分**、队友面板 5 行、地图隐藏后能
  恢复、图传为精确 16:9、四块信息件的几何都落在画面矩形内；
- 专注模式：全屏 + 侧栏/日志/诊断隐藏 + HUD 全部保留且仍在画面内 + 图传变宽；`Esc` 一次退到底；
- 纯全屏与专注态互斥、纯全屏下无 HUD；
- 1024×720 紧凑窗口与最小窗口下，图传不被下方工具行压住；日志展开（最坏态）时布局仍不重叠。

失败时标准错误里会带上该组每个子项的实际取值（例如"图传底 / 工具行顶""画面矩形 / 各信息件底边"），
便于直接定位是几何问题还是状态问题。证据除整窗截图外，还会另存一张**只有 HUD 的原尺寸**位图
（`<前缀>-hud.png`）：整窗截图缩放后看不出 HUD 内部是否被裁，这张可以。

`--metrics` 输出中 `operator_*` 字段的含义：`operator_hud_enabled` 是「信息叠加」开关状态，
`operator_teammate_rows` 是队友面板行数（固定 5）；`operator_hud_visible` / `operator_map_visible` /
`operator_focus_fullscreen` 取的是**输出时刻**的实际状态 —— 自检结束会把界面恢复到原页面，所以这三项
在自检后为 `false` 属正常，结构性问题以 `--ui-checks` 的返回值为准。
